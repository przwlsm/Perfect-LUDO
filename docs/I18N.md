# Translations

The app is translated with [i18next](https://www.i18next.com) and
[react-i18next](https://react.i18next.com). The phone's language is read with
`expo-localization`, and players can override it in **Settings → Language**.

Shipped languages (picker order): **English** (source), Hindi, Bengali,
Marathi, Telugu, Tamil, Gujarati, Kannada, Spanish (Latin American),
Portuguese (Brazilian) and Arabic (right-to-left).

## Where things live

```
src/presentation/i18n/
  languages.ts         every language: native name, direction, script
  resources.ts         every catalogue, by language and namespace
  index.ts             the i18next instance (initialised synchronously)
  LanguageProvider.tsx saved choice, font loading, direction, Settings hook
  ScriptContext.ts     which script's fonts Text should use
  useCatalogText.ts    names of game modes, cosmetics and rarities
  i18next.d.ts         makes every key type-checked against English
  catalogues.test.ts   every language has the same keys/placeholders/plurals
  locales/<lang>/<namespace>.json
```

Namespaces, one per area: `common` (shared words, nav, modes, cosmetics),
`onboarding`, `system` (updates, crash screen), `settings`, `home`, `game`,
`online`, `social`, `store`, `rewards`, `account` (profile, sign-in, feedback).

## Writing translatable code

1. **Every visible string goes through `t`**, including `accessibilityLabel`,
   `accessibilityHint`, `placeholder`, `Alert` and `Share` text.

   ```tsx
   const { t } = useTranslation(['store', 'common']);
   <Text>{t('buy.title')}</Text>               // store:buy.title
   <Text>{t('common:actions.back')}</Text>      // another namespace
   ```

   Keys are type-checked: a typo or a key missing from the English file is a
   compile error.

2. **Whole sentences, never fragments.** Word order differs between languages
   (Hindi puts the verb last), so a sentence is one key with placeholders:
   `"wonCoins": "You won {{amount}} coins!"`. Never write
   `t('you') + amount + t('coins')`.

3. **Plurals** use `count` and the language's plural forms:

   ```json
   "players_one": "{{count}} player",
   "players_other": "{{count}} players"
   ```

   `t('players', { count: 3 })`. Hindi uses `one`/`other`; the catalogue test
   checks each language has every form it needs (Arabic has six).

4. **No translated text at module level.** Constants hold ids or keys; translate
   while rendering. Module-level `t()` calls freeze the language at startup.

5. **State holds keys or codes, not translated text**, so switching language
   updates messages already on screen (see `SettingsScreen`'s `result` state).

6. **Styled parts of a sentence** use `<Trans>` with named components rather than
   splitting the sentence into keys.

7. **Outside React** (a plain function called during render), use
   `import { i18n } from '../i18n'` and `i18n.t(...)` at call time.

8. **The domain stays language-free.** Domain code returns ids and codes; the
   presentation layer maps them to keys. Domain English (e.g. `VARIANT_INFO`,
   `COSMETICS[].name`) is kept for tests and logs; screens use
   `useCatalogText()` instead.

9. **Numbers and dates** use `formatCount` from `Kit`, `formatNumber`/`formatDate`
   from `i18n/format.ts`, or `toLocaleString(numberLocale())`. Never pass
   `i18n.language` directly: Bengali, Marathi and Arabic would switch to their
   own digits (১২৩, १२३, ١٢٣) while dice, timers and scores show 0-9.
   `numberLocale()` keeps each language's grouping (12,34,567 in Indian
   languages) with Latin digits.

10. **Leave room.** Hindi runs 20-40% longer than English. Avoid fixed widths for
    text; use `numberOfLines` with `adjustsFontSizeToFit` only where space is
    truly fixed.

11. **Not translated:** the `LUDO RUMBLE` wordmark, ids, route names, emoji,
    "XP", and server-defined text (see Known gaps).

## Fonts and scripts

`Text` and `TextInput` (`components/AppText.tsx`) pick the family for the
current script and weight from `theme/typography.ts`:

| Script     | Languages                    | Family           | Weights bundled         |
| ---------- | ---------------------------- | ---------------- | ----------------------- |
| Latin      | English, Spanish, Portuguese | Outfit           | 400-900                 |
| Devanagari | Hindi, Marathi               | Baloo 2          | 400, 500, 600, 700, 800 |
| Bengali    | Bengali                      | Baloo Da 2       | 400, 600, 800           |
| Telugu     | Telugu                       | Baloo Tammudu 2  | 400, 600, 800           |
| Tamil      | Tamil                        | Baloo Thambi 2   | 400, 600, 800           |
| Gujarati   | Gujarati                     | Baloo Bhai 2     | 400, 600, 800           |
| Kannada    | Kannada                      | Baloo Tamma 2    | 400, 600, 800           |
| Arabic     | Arabic                       | Baloo Bhaijaan 2 | 400, 600, 800           |

The Baloo families are one rounded, playful design drawn for each script, so
every language keeps the same look. To keep the app small (each weight is
150-420 KB), scripts other than Devanagari bundle three weights: 500 renders
as 400, 700 as 600, and 900 as 800 (`threeWeights` in `typography.ts`).
Font files are required individually in `LanguageProvider.tsx`, so unused
weights are never bundled.

Devanagari gets slightly smaller glyphs and taller line height
(`SCRIPT_METRICS`) so marks above and below the line are not clipped, and
`letterSpacing` is reset to 0, because tracking breaks the headline that joins
Devanagari letters. `textTransform: 'uppercase'` has no effect on scripts
without case, so uppercase labels simply show the translated text. Fonts for
a script load only when a language using it is chosen; the splash stays up
until they are ready.

## Adding a language

1. Add it to `LANGUAGES` in `languages.ts` (native name, `dir`, `script`).
2. Copy `locales/en/` to `locales/<code>/` and translate every value. Keep keys
   and `{{placeholders}}`; add the plural forms the language needs.
3. Register the files in `resources.ts`.
4. Add it to `supportedLocales` for `expo-localization` in `app.json`, so
   Android 13+ lists it under the system's per-app language setting.
5. New script? Add its fonts to `FONTS_BY_SCRIPT` and `SCRIPT_METRICS`
   (`theme/typography.ts`) and to `SCRIPT_FONTS` (`LanguageProvider.tsx`).
   The Baloo 2 family has matching faces for other scripts: Baloo Bhaijaan 2
   (Arabic), Baloo Da 2 (Bengali), Baloo Thambi 2 (Tamil), Baloo Tammudu 2
   (Telugu), Baloo Tamma 2 (Kannada), Baloo Chettan 2 (Malayalam), Baloo Bhai 2
   (Gujarati), Baloo Paaji 2 (Gurmukhi).
6. Right-to-left (e.g. Urdu, Persian): set `dir: 'rtl'`. RTL support is already
   on (`supportsRTL` in `app.json`) and handled as described under
   **Right-to-left** below.
7. Run `npx jest src/presentation/i18n`. Have a native speaker review the text
   on a device before release.

## Right-to-left

Arabic mirrors the whole interface: rows run right to left and text aligns
right. Choosing it (or leaving it) reloads the app once, because React Native
fixes the direction at startup (`applyDirection` in `LanguageProvider.tsx`).

Helpers in `i18n/rtl.ts`:

- `keepLtr` — the Ludo board, thumbnails and the game table stay left-to-right.
  The board is a physical object: mirroring it would reverse the direction
  pieces travel and put each player's panel at the wrong corner.
- `mirrorInRtl` — style for icons that point along the reading direction
  (back `‹`, chevrons, arrows). Up/down icons and symmetric ones need nothing.
- `forwardArrow` — `→`, or `←` in RTL, for arrows inside text.

Use `start`/`end` (`marginStart`, `paddingEnd`, `alignSelf: 'flex-start'`)
rather than `left`/`right` in new layouts so they mirror automatically.

Notes from the translators:

- English sometimes says "coin" for a board piece ("Two coins on one square").
  Every language translates those as _piece_, keeping _coins_ for currency.
- Spanish, Portuguese and Arabic translate the mode name "Kill & Go"; the
  Indian languages transliterate it. Decide whether it is a brand name.
- Marathi and Gujarati past tenses carry gender: "X won" uses the masculine
  form, as the app does not know the player's gender.
- Arabic uses all six plural forms and writes arrows as ← (forward in RTL).
- Share and invite messages use the informal "you" where a player writes to a
  friend (Bengali তুমি, Marathi तू); everything else is polite.

## Known gaps

- **Server messages.** Errors raised by Supabase functions (`raise exception
'...'` in `supabase/migrations`) reach the player in English. The fix is for
  the server to return an error code and the app to map codes to keys.
- **Server-stored text.** Mission titles (`get_rewards`), and the title and
  message of rows in `notifications` (challenges, friend requests), are written
  in English by the database. Store a type code plus parameters instead and
  build the sentence in the app.
- **Application-layer warnings.** `AccountProfiles` and the feedback validator
  return English sentences; the presentation layer maps the known ones to keys
  by exact text (`ProfileProvider`, `useFeedback`). Prefer error codes there too.
- **Store-version message.** `app_versions.message` is shown as written; add a
  per-language column if needed.
- **Review.** The Hindi text should be reviewed by a native speaker on a device
  before release. Wordings worth a second opinion: level names (ROOKIE →
  नौसिखिया), "Easy going" → आराम से, "Set your table" → अपनी टेबल सजाएँ, and the
  Hindi player-count label under the narrow 2-8 player buttons.
